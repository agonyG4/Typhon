# Presentation Modes v1 Correctness Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make commit `7642820` truthful end to end: causal surface metadata, worker parity, asynchronous Async fence readiness, real Async qualification, conservative scene policy, correct Content Type ownership, and evidence-backed feedback.

**Architecture:** Preserve the existing typed `OutputPresentationMode` and frozen `OutputTransaction` design. Add narrowly scoped state/validation modules at the KMS and native-output boundaries, so policy consumes facts proven by the current frame and submission paths share one typed flag contract. Keep optional protocol metadata non-fatal and leave VRR/FIFO/Commit Timing architecture unchanged.

**Tech Stack:** Rust 2024, Wayland server protocol generated by `wayland-protocols`, DRM Atomic/legacy KMS, existing native event loop and explicit-sync infrastructure, Cargo tests.

## Global Constraints

- Preserve `wp_tearing_control_v1`, `wp_content_type_v1`, `SurfacePresentationHint`, `SurfaceContentType`, and `OutputPresentationMode`.
- Do not implement VRR, rewrite FIFO/Commit Timing, or use value equality for mutation causality.
- Async requires exact KMS qualification, render-fence readiness, solitary fullscreen state, safe cursor/metadata transitions, and a free KMS lane.
- Async composited commits omit primary `IN_FENCE_FD` only after userspace readiness; VSync retains existing explicit-sync behavior.
- Unsupported optional DRM Content Type enums fall back to `Graphics`; protocol requests never become output/session errors.
- Keep `OBLIVION_ONE_TEARING=off` as the default and do not claim full validation on Windows.
- Keep every changed Rust source within repository layout limits.
