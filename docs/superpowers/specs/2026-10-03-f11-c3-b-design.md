# F11-C3-B — Incoming XDND terminal bridge

## Goal

Complete the root-proxy X11-to-Wayland XDND path through Drop and terminal
Finished, then publish the root proxy only after that path is ready.

## Approved architecture

`CompositorState::active_drag` remains the only drag authority. The XWM keeps
one direction-typed incoming session with explicit wire phases. An accepted
wire Drop is submitted as an exact-offer semantic event and the runtime
acknowledges the compositor result before starting the terminal deadline.
Post-Drop MIME receives stay attached to the same incoming offer and use the
frozen Drop timestamp for new conversions. Existing conversions keep their
original Position timestamp.

The canonical `SourceFinished` transition is the only success/failure evidence
for the external X11 source. Copy sends one v5 `XdndFinished`; Move first runs a
dedicated, bounded `DELETE` Selection conversion. The XWM may retain state only
for this bounded wire cleanup after canonical completion.

Root discovery has explicit generation-qualified authority. Startup initializes
all XWM and DND machinery before one call to the existing server-grab
`acquire_root_proxy` primitive. A valid foreign owner is preserved and blocks
reverse discovery for the generation. While owned, root property changes cause
one asynchronous verification; loss fails the exact active bridge closed and
never triggers automatic reacquisition.

Only XDND v5 sources may receive accepted terminal Status. v4 metadata and
message parsing remain safe, but v4 Status is rejected and v4 Drop cannot reach
canonical Drop. Ask may finish only as Copy or Move. Real-application
qualification remains F11-D; C4 deadline-extension policy remains unstarted.

## Components and validation

- `dnd_wire.rs` owns typed Drop decoding and Finished encoding, with raw-word
  unit tests.
- `dnd_incoming.rs` and its metadata/transfer modules own root authority,
  incoming wire phases, bounded verification, Drop admission, timestamps,
  DELETE, terminal cleanup, and phase-sensitive teardown.
- `dnd_metadata.rs`, `service.rs`, `server_xwayland.rs`, and runtime XWayland
  synchronization carry exact Drop and terminal-cancel requests and their
  acknowledgements to the canonical compositor APIs.
- XWM event normalization intercepts root `XdndProxy` PropertyNotify before
  generic window property normalization.
- Focused fake-X protocol tests cover Copy, Move, failures, authority loss,
  version policy, and cleanup. `docs/XWAYLAND.md` records the v5 boundary.
