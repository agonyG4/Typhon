# F11-C4 — Reverse XDND terminal lifetime hardening

## Goal

Replace the fixed post-Drop timeout with a progress-aware but bounded lifetime,
retain the reviewed XDND v5 productive-terminal boundary, and preserve the
F11-C3-B terminal and root-authority invariants.

## Approved architecture

`IncomingDndWirePhase::AwaitingWaylandFinish` remains the sole owner of the
terminal lifetime. It carries a renewable `deadline_ns`, an immutable
`hard_deadline_ns`, and the existing `cancel_submitted` state. The canonical
Drop acknowledgement starts a 60-second progress lease and a 10-minute
absolute cap. Valid activity from an exact live transfer may move the lease to
`min(now + 60 seconds, hard_deadline_ns)`, but never earlier or beyond the cap.
Once cancellation is submitted, `deadline_ns` is the existing one-second
cancellation fallback and transfer activity cannot change it.

One helper in the terminal ownership module validates a transfer's exact ID,
offer, generation, requestor mapping, current canonical-started session, live
Wayland sink, terminal phase, cancellation state, and hard-cap boundary before
renewing the lease. It does not require current root proxy ownership: root loss
blocks new admission but cannot freeze committed terminal work.

Only successful post-Drop request admission, validated non-None SelectionNotify,
validated direct/INCR property replies, and positive-byte sink writes count as
progress. Issuing X requests, raw property notifications, handshake deletes,
readiness, zero-byte writes, interrupted or blocked writes, malformed/stale
traffic, and X-side draining after sink loss do not count. The independent
30-second transfer idle timeout remains unchanged.

Either terminal deadline expiring goes through canonical `CancelAfterDrop`.
The existing fallback leaves the exact session alive long enough for a queued
canonical `SourceFinished` to win. Transfer EOF is not terminal completion and
the canonical `SourceFinished` transition remains the only terminal
success/failure authority. One-shot cleanup continues to emit at most one
`XdndFinished`.

The v5-only productive-terminal policy is reviewed and intentionally retained.
Pre-v5 metadata and message parsing remain safe, but v2-v4 cannot receive
accepted terminal Status or enter productive canonical Drop/Finished handling.
Before v5, Finished cannot truthfully carry the late failure and action
semantics this bridge can encounter.

## Event-loop boundary

The native cycle drains XWayland reactor work and synchronizes DND before
handling an actionable timer. Managed XWM draining remains bounded at 256 and
can request a continuation. Add a synthetic same-timestamp regression showing
that progress actually processed by that drain renews the lease before
expiration. Inspect the budget-exhausted path without increasing budgets or
suppressing deadlines globally. Change runtime ordering only if a focused
regression proves that an already deliverable, legitimate progress event loses
to terminal expiration under the actual cycle order.

## Scope and validation

Keep C4 within incoming DND lifetime state, transfer validation, focused fake-X
regressions, and XWayland documentation. Do not start F11-D qualification or
change outgoing DND, canonical active-drag authority, RandR publication, cursor
ownership, or unrelated XWayland behavior.

Use synthetic monotonic timestamps and exact deadlines in regressions. Validate
formatting, all requested focused tests, the retained C3-B lifecycle and wire
regressions, repository-wide tests, clippy, and source layout with Cargo output
under `/mnt/Aether/Desktop/GitHub/Typhon-target`.
