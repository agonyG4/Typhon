# Typhon Locked Cursor Visual Reveal Qualification v1.1 Design

## Context

The v1 trace established the locked-cursor reveal lifecycle and the cursor presentation chain, but two observability gaps remain. Synchronous KMS submissions are not represented by the same submission evidence as worker submissions, and the pageflip trace currently resolves reveal ownership from mutable compositor-global state. The latter can misattribute an older physical submission when a newer reveal begins before the older pageflip arrives.

This change is Gate 1 observability work only. It does not correct cursor placement, alter cursor scheduling, or enter Gate 2 semantic cursor correction.

## Goals and invariants

- Preserve the existing reveal and cursor trace event chain, opt-in environment variable, cursor state accessors, revision model, worker ownership, sidecars, pageflip promotion, and `PresentedCursorState`.
- Emit one canonical cursor KMS submission representation for worker and synchronous cursor-only and primary-plus-cursor submissions.
- Bind a reveal snapshot to the exact physical identity `(output_generation, crtc_id, PageFlipToken)` before an asynchronous boundary is crossed.
- Keep per-reveal first-visible bookkeeping independent for overlapping reveals.
- Compare every known visual invariant at first visibility: position, revision, delivery, hotspot, framebuffer, image generation, and source. `unknown` remains distinct from `false`.
- Make all new ledger state trace-only and disabled by construction when `TYPHON_CURSOR_PRESENTATION_TRACE` is not enabled.
- Keep the trace ledger bounded and explicit about overflow.

The implementation must not change KMS ordering, worker selection or replacement, cursor visibility policy, pointer coordinates, client cursor semantics, input cadence, `NativeInputEpoch`, or any other runtime policy.

## Design

### Exact KMS assignment semantics

`src/native/kms/atomic.rs` will expose a traceable, trace-only-friendly cursor assignment description generated by the same helper that writes cursor plane properties. The helper will preserve the current behavior for absent cursor planes, hidden cursors, and visible cursors. In particular, enabled geometry will use the real framebuffer, source rectangle, hotspot-adjusted CRTC position, and dimensions; disable will be represented by the actual zero `FB_ID`/`CRTC_ID` assignment; unchanged will not invent an assignment.

The canonical `CursorKmsSubmitTrace` formatter will take that assignment description plus the physical token, output generation, CRTC, transaction identity, revision/epoch when available, transport, and submission kind. It will emit the same field names for worker and synchronous paths. Unavailable values are rendered as `unknown`, never as fabricated zeroes. The formatter is called only when trace is enabled.

The formatter is wired at the four physical submission families:

1. worker cursor-only;
2. worker primary-plus-cursor, including sidecar promotion;
3. synchronous cursor-only;
4. synchronous primary-plus-cursor.

The existing worker scheduling, sidecar handoff, and KMS submission policy remain unchanged.

### Frozen reveal identity ledger

`NativeRuntime` receives an `Option<CursorRevealTraceLedger>`. The option is constructed only when presentation tracing is enabled. The ledger contains bounded FIFO collections for:

- physical submissions keyed by `(output_generation, crtc_id, PageFlipToken)`, each holding a frozen reveal snapshot and its physical cursor expectation;
- reveal lifecycle state keyed by the reveal’s backend constraint identity, including whether first-visible evidence has already been emitted and whether the reveal is terminal.

The capacity is small and fixed (32 entries for each bounded collection). On overflow the ledger emits `event=cursor_reveal_trace_overflow`, retires the oldest safe trace entry, and continues. Ledger retirement can only remove diagnostics; it never drops or changes a real KMS submission.

The snapshot includes the reveal constraint, final position, visibility request, expected cursor epoch/revision, expected delivery and position/hotspot, framebuffer/image-generation/source metadata where available, and the presentation ownership. It is captured when a cursor state receives its real `PageFlipToken`, not merely when unlock finalization runs. Worker snapshots travel through the existing sidecar/owner metadata until the main runtime sees the worker’s submitted event; synchronous snapshots are registered after the real submission returns and its physical identity is known.

At pageflip, `trace_presented_cursor` looks up and removes the exact ledger entry using the pageflip identity’s token, output generation, and CRTC. It never reads the current compositor-global reveal authority. A late pageflip therefore retains the reveal that owned its original submission even if another reveal has already started.

### Reveal terminals and first-visible evidence

Starting a new reveal terminally classifies an older still-active reveal as `superseded_by_new_reveal`; any in-flight physical entries remain until their pageflips arrive so they retain attribution. A reveal whose final visibility request is false emits `event=cursor_reveal_terminal reason=no_visible_cursor_requested` immediately and cannot later claim an unrelated visible cursor. Other terminal reasons remain explicit and bounded.

First-visible state is tracked by reveal identity, not by one compositor-global boolean. The first pageflip that transitions from hidden to visible consumes that reveal’s slot. The evidence reports `position_match`, `revision_match`, `delivery_match`, `hotspot_match`, `framebuffer_match`, `image_generation_match`, `source_match`, `visual_match`, and `overall_match`, each as `true`, `false`, or `unknown` where appropriate. `overall_match` is true only when all required known invariants match and is false when a required known invariant differs; missing important information produces `unknown`.

Hardware cursor and software/embedded-in-primary cursor presentations both carry ownership. For software ownership, the primary composition submission is the physical identity that owns the expected cursor state. Equality is used only to compare known representations; coordinates never infer ownership.

### Trace-disabled behavior

With presentation tracing disabled, the runtime has no cursor reveal ledger, no frozen snapshots, no first-visible bookkeeping, no trace formatting, and no new time or scheduling work. The production cursor state and KMS paths execute the same semantic operations as before. Unit coverage asserts state neutrality rather than merely checking that no output line was printed.

## Data flow

```text
unlock lifecycle
  -> reveal authority + revision/source snapshot
  -> actual cursor KMS/primary submission allocates PageFlipToken
  -> ledger bind: (output_generation, crtc_id, token) -> frozen snapshot
  -> physical submission trace (canonical payload)
  -> pageflip identity lookup and removal
  -> cursor_presented
  -> per-reveal first-visible compare/terminal
```

For worker submissions, the snapshot is carried in existing cursor owner metadata and bound by the main runtime at `KmsWorkerEvent::Submitted`. For synchronous submissions, the binding occurs at the synchronous call site after the backend has returned the token. Neither route changes the event ordering or the backend’s assignment.

## Error handling

- Missing ledger entry: emit presentation evidence with unknown reveal attribution and continue pageflip processing.
- Missing trace-only KMS pipeline metadata: emit the canonical event with unavailable fields as `unknown`; do not invent identifiers.
- No cursor plane for a hidden cursor: preserve the existing successful no-assignment behavior and report the actual equivalent assignment state.
- Visible cursor without a cursor plane: preserve the existing unsupported error; the trace must not mask or convert it.
- Ledger overflow: emit an explicit overflow event and retire only the oldest safe diagnostic entry.
- Terminal reveal with pending submissions: retain physical entries until their pageflip so ownership remains attributable, then retire the reveal state.

## Verification strategy

Tests will cover the ledger and match helpers directly and the integration points through focused production tests:

- overlapping reveals A/TA and B/TB delivered in either order;
- an A pageflip arriving after B starts;
- independent first-visible slots;
- no-visible reveal terminal followed by unrelated visible B;
- stale same-position state with old revision/image/hotspot/framebuffer;
- exact matching state with all available fields true;
- trace-disabled state neutrality;
- exact synchronous cursor-only and primary-bundled KMS payloads;
- worker cursor-only, primary-plus-cursor, and sidecar regression;
- existing cursor trace, pointer unlock, cursor policy, `NativeAtomicCursor`, pageflip, synchronous plane-delta, KMS worker, and sidecar suites.

The required repository verification remains:

```text
rtk cargo fmt --check
rtk cargo check --locked --all-targets
rtk cargo clippy --locked --all-targets -- -D warnings
rtk cargo test --locked
rtk git diff --check
```

The final qualification report will record exact starting and ending HEADs, RED/GREEN results, worker and synchronous coverage, frozen identity and bounded ledger behavior, disabled neutrality, no-visible terminal behavior, and the Gate 1 boundary. It will explicitly state that no semantic cursor correction was implemented and that native A/B capture remains the next step.
